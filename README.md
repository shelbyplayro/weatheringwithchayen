# ฝนจะตกไหมชาเย็น

หน้าเว็บหน้าเดียวสำหรับดูว่าพิกัดหนึ่งจะมีฝนในอีก 0–4 ชั่วโมงหรือไม่ ค่าเริ่มต้นคือพิกัดสวนที่ อ.คีรีรัฐนิคม จ.สุราษฎร์ธานี (9.032760, 98.944311)

## ข้อมูลที่ใช้

| แหล่ง | ใช้ทำอะไร |
|---|---|
| RainViewer (ภาพเรดาร์ย้อนหลัง 2 ชม. ทุก 10 นาที) | หาตำแหน่ง ความเร็ว และทิศของกลุ่มฝน แล้วเลื่อนไปข้างหน้า (0–2 ชม.) |
| Open-Meteo Ensemble API (ECMWF, GFS, ICON) | สัดส่วนสมาชิก ensemble ที่ให้ฝน ≥0.1 มม./ชม. |
| Open-Meteo Forecast API (ECMWF, GFS, ICON, JMA, GEM, CMA) | ปริมาณฝนรายชั่วโมงและ precipitation probability, ลมระดับ 700 hPa ใช้แทนความเร็วกลุ่มฝนเมื่อเรดาร์เห็นฝนน้อยเกิน |
| OpenStreetMap | แผนที่พื้นหลังของภาพเรดาร์ |

ไม่ต้องใช้ API key ทุกอย่างดึงในเบราว์เซอร์ของผู้เปิดหน้าเว็บ และรีเฟรชเองทุก 10 นาที

## วิธีรวมตัวเลข

ความน่าจะเป็นต่อช่วง 15 นาที = w·(เรดาร์) + (1−w)·(แบบจำลอง) โดย w = (1 − t/120)^1.2 เมื่อ t คือนาทีข้างหน้า น้ำหนักเรดาร์จึงเป็น 1 ที่ตอนนี้ ราว 0.44 ที่ 60 นาที และ 0 ตั้งแต่ 120 นาทีขึ้นไป

ฝนพาความร้อนที่ก่อตัวใหม่เรดาร์จะยังไม่เห็น ตัวเลขช่วงบ่ายจึงพึ่งแบบจำลองเป็นหลัก

## บันทึกความแม่นยำอัตโนมัติ

`.github/workflows/chayen-log.yml` รันทุก 20 นาทีบน GitHub Actions เรียก `tools/log.mjs` ซึ่งใช้สูตรเดียวกับหน้าเว็บ (อ่านจาก `index.html` โดยตรง) แล้วเขียนผลลง branch `data`:

| ไฟล์ | เนื้อหา |
|---|---|
| `forecasts.csv` | พยากรณ์ 16 ช่วง × 15 นาทีของแต่ละรอบ แยกค่ารวม ค่าเรดาร์ และค่าแบบจำลอง |
| `observed.csv` | ภาพเรดาร์ทุก 10 นาที: มีฝนบนจุดสวนหรือไม่ และสัดส่วนฝนในรัศมี 1 กม. และ 5 กม. |
| `wind.csv` | ลมที่สวน (10 ม., กระโชก), ความเร็วกลุ่มฝนจากเรดาร์เทียบกับลมระดับบน, ระยะ/ทิศ/ETA ของฝนที่ใกล้ที่สุด ใช้ตรวจภายหลังว่าพยากรณ์พลาดตอนลมแบบไหน |
| `reports.csv` | รายงานจากปุ่ม "ฝนตกอยู่ / ไม่ตก" ในแอป เทียบกับพยากรณ์ล่าสุด พยากรณ์ล่วงหน้า 1–2 ชม. และเรดาร์ ±10 นาที |
| `verify.json` | Brier score, skill เทียบค่าเฉลี่ย, แยกตามระยะเวลาล่วงหน้า, ตาราง reliability และสรุปผลเทียบกับรายงานจริง (`reports`) |

ค่าจริงที่ใช้ตัดสินคือเรดาร์ตรงสวน: ช่วง 15 นาทีนับว่า "ฝนตก" ถ้ามีภาพเรดาร์อย่างน้อยหนึ่งภาพในช่วงนั้นเห็นฝน

## ปุ่มแจ้งสถานการณ์จริง

ปุ่ม "ไม่ตก / ฝนตกอยู่" ในการ์ดชาเย็น (กดฝนตกอยู่แล้วเลือกระดับ นิดเดียว / ธรรมดา / หนัก)เปิดหน้า New issue ของ repo นี้พร้อมข้อความกรอกไว้ให้ กด Submit แล้ว workflow จะรันทันทีและนับรายงานนั้นเข้า `reports.csv` (คอลัมน์ `intensity` = light / moderate / heavy เฉพาะตอนฝนตก) นับเฉพาะ issue ที่เจ้าของ repo หรือผู้ร่วมงานเปิด

## ชาเย็น กับ ชานม

หน้าหลักมีเพื่อนสองตัวขนาดเท่ากัน ชาเย็นดมกลิ่นฝน (โอกาสฝน) ชานมดูลม (ทิศ ความเร็ว กระโชก และฝนที่ใกล้ที่สุดกำลังเข้าใกล้หรือเคลื่อนออก พร้อมเวลาโดยประมาณ) ข้อมูลของชานมใช้แสดงผลและบันทึกลง `wind.csv` เท่านั้น ยังไม่ปรับตัวเลขโอกาสฝน

รูปชานมใส่ที่ `CHAONM_STICKERS` ใน `index.html` (คีย์ `calm, light, strong, gust, approach, leave, away, unsure`) เพิ่มท่า `run, sniff, pinwheel` สำหรับรายชั่วโมง ท่ากลางคืน `n_sleep, n_zz, n_wrap, n_rain` ท่าฝนตกที่สวน `shelter` และท่าไม่มีข้อมูล `nodata`

## รูปแชร์

ปุ่มกล้องสร้างรูป 1080 px: สรุปฝนกับลม เพื่อนสองตัว โอกาสฝนราย ชม. และภาพเรดาร์ล่าสุด (วง 10 / 25 / 50 กม.) ถ้าอ่านภาพเรดาร์ไม่ได้ รูปจะสั้นลงและไม่มีส่วนเรดาร์

## รายงานจากสวนปรับพยากรณ์บนหน้าจอ

หลังกดรายงาน แอปใช้รายงานนั้นแทนเรดาร์สำหรับ "ตอนนี้" ทันที (`Core.applyReport`): แจ้งฝนตก = ถือว่าฝนตกอยู่ และยกโอกาสฝน 1 ชม. ข้างหน้าตามระดับ (หนักค้างนานกว่าเบา) แจ้งไม่ตก = ถือว่าไม่ตก และลดโอกาส 30 นาทีแรก น้ำหนักเต็ม 15 นาที แล้วลดจนหมดที่ 45 นาที มีผลเฉพาะเครื่องที่กดรายงาน และไม่กระทบ `tools/log.mjs` กับค่า forecast ที่แนบไปใน issue (ใช้ค่าก่อนปรับเสมอ)

## สเกลคำพูด (ใช้ทุกจุด)

| โอกาสฝน | คำบนหน้าจอ | ท่าชาเย็น |
|---|---|---|
| ต่ำกว่า 30% | ฝนไม่น่ามา | ท่าแดด/งีบ |
| 30–59% | มีลุ้นฝนช่วง … (ไม่บอกเวลามาถึง) | เอียงคอ ฟุดฟิด |
| 60–79% | ฝนน่าจะมาในอีกราว … | หูตั้ง / กางร่มรอ |
| 80% ขึ้นไป | ฝนมาแน่ ในอีกราว … (ถ้าเรดาร์ไม่เห็นฝนและเกิน 1 ชม. จะใช้ "น่าจะมา") | หูตั้ง / กางร่มรอ |
| ฝนตกที่สวน | ฝนตกที่สวนแล้ว | ท่าเล่นน้ำ |

ค่าอยู่ที่ `Core.P_MAYBE / P_LIKELY / P_SURE`

## เวอร์ชันและป๊อปอัปอัปเดต

เลขเวอร์ชันอยู่ที่บรรทัดบนสุดของ `index.html`:

```html
<meta name="app-version" content="2.0.0">
<meta name="app-notes" content="สรุปสั้น ๆ ว่ารอบนี้เปลี่ยนอะไร">
```

ทุกครั้งที่อัป `index.html` ใหม่ให้เปลี่ยนเลขนี้ (เลขหลังสุด = แก้เล็กน้อย, เลขกลาง = เพิ่มความสามารถ, เลขหน้า = เปลี่ยนใหญ่) หน้าเว็บที่เปิดค้างอยู่จะเช็คกับไฟล์บนเซิร์ฟเวอร์ตอนเปิด ทุก 30 นาที และตอนสลับกลับมาที่แอป ถ้าเลขไม่ตรงจะขึ้นป๊อปอัป "มีเวอร์ชันใหม่" พร้อมข้อความใน `app-notes` เลขเวอร์ชันปัจจุบันแสดงที่ท้ายหน้า
